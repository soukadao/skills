# Task Decomposer

対象分野に関係なく、同じ判断基準で作業を小さな実行タスクへ分解する。最終出力は分解したタスクの一覧だけにする。

## 分解判断

各タスクは次の条件をすべて満たすまで分割または書き直す。

- **時間**: 1-60分で完了する。秒単位の作業も目安は1分と書く。
- **単一成果**: 1タスクには、1つの成果または1つの確認結果だけを持たせる。
- **具体性**: 対象、操作、期待結果が分かる文にする。
- **観測可能性**: 完了条件には、確認できる文言、状態、回答、記録、表示、値、結果を書く。
- **判断分離**: 依頼者や顧客の判断が必要な内容は、作業に混ぜず確認タスクにする。
- **確定前提**: `確定した`、`承認済み`、`決定した` を使う場合は、その判断を記録する確認タスクを先に置く。
- **具体値**: `正常値`、`不正値`、`改善案`、`対象データ` だけで終えず、実際の値、文言、条件を書く。未確定なら確認タスクにする。
- **条件固定**: 1つの条件だけを確認する場合は、確認対象以外の条件を固定する。
- **低依存**: 「Aの結果がないとBを判断できない」場合だけ依存にする。同じ資料、画面、相手、ファイルを扱うだけでは依存にしない。
- **出力制限**: ユーザーが求めていない限り、担当者やAgent名の列は出さない。

## 分割するサイン

次の表現が含まれるタスクは、より小さなタスクに分ける。

- 抽象動詞だけ: `対応する`、`進める`、`整理する`、`検討する`、`確認する`、`レビューする`、`作成する`
- 複数対象: `A・B・C`、`AとB`、`各項目`、`複数ケース`
- 曖昧な対象: `変更箇所だけ`、`必要な箇所`、`関連するもの`
- 複数工程: 作成して確認する、修正して共有する、問い合わせて回答を反映する
- 複数判断: 案を作る、承認を得る、反映する、結果を確認する

## 分解の進め方

1. 事実と判断を分ける。
   - 調べれば分かることは調査タスクにする。
   - 正しさ、優先順位、採用可否、公開可否などは確認タスクにする。

2. 大きな作業を単一成果へ分ける。
   - 「調査してまとめる」は、調査対象の確認、情報抽出、要約作成、妥当性確認に分ける。
   - 「資料を作成する」は、章立て作成、各章の本文作成、図表作成、誤字確認、共有文作成に分ける。
   - 「問い合わせる」は、確認事項の整理、送付文作成、送付、回答記録に分ける。
   - 「A・B・Cを作る」は、Aを作る、Bを作る、Cを作るに分ける。

3. 確認タスクを具体化する。
   - 何を、どの観点で、どうなればOKかを書く。
   - 依頼者や顧客に聞く場合は、何を聞き、どんな回答が得られれば完了かを書く。
   - 例: メール空欄エラーを確認するなら、氏名欄と問い合わせ内容欄には正常な具体値を入れる。

4. 依存を最小にする。
   - 順番にやると楽というだけなら依存にしない。
   - 確認待ちの内容に依存する作業は、依存に確認タスクを書く。

## 出力形式

最終出力はタスク一覧だけにする。目的、前提、確認事項、実行順、見直し結果などの説明セクションは出さない。

確認が必要なものは、説明ではなく表の中の確認タスクとして入れる。

```markdown
| ID | タスク | 目安 | 依存 | 完了条件 |
|---|---|---:|---|---|
| T1 | 対象に対して具体的な操作を行う | 10分 | なし | 観測可能な期待状態になる |
```

確認質問が必要な場合は、計画を確定する前に最大3問までに絞って質問する。質問後に計画を出す場合も、最終出力はタスク一覧だけにする。

## 書き換え例

- 悪い例: 資料を作成する
- 良い例: 提案資料の「導入背景」章に、現状課題を3項目で記述する
- 悪い例: 顧客に確認する
- 良い例: 郵便番号をハイフンなし表記に統一してよいか顧客に確認する
- 悪い例: 氏名・メール・問い合わせ内容のラベル改善案を1案ずつ作る
- 良い例: 氏名欄のラベル改善案を1案作る
- 悪い例: メール欄を空欄にして送信した時のエラーメッセージを記録する
- 良い例: 氏名欄に `山田太郎`、問い合わせ内容欄に `資料請求を希望します` を入力し、メール欄を空欄にして送信した時のエラーメッセージを記録する

## 最小タスク例

- 完了メッセージの `xxxxしました。` を `yyyyしました。` に変更する。目安: 1分。完了条件: 完了メッセージに `yyyyしました。` と表示される。
- 郵便番号入力欄の placeholder を `123-4567` から `1234567` に変更する。目安: 1分。完了条件: 郵便番号入力欄の placeholder がハイフンなしの `1234567` になっている。
- 提案資料の表紙の日付を `2026/06/07` から `2026/06/08` に変更する。目安: 1分。完了条件: 表紙の日付が `2026/06/08` になっている。
- 議事録の参加者欄に `山田太郎` を追加する。目安: 1分。完了条件: 参加者欄に `山田太郎` が含まれている。
