## 共通仕様

- `drawio` の `open_drawio_xml` toolを使用する
- 凡例は`assets/legend.xml`を参考し、他の図形と被らないように左下に配置する
- 線のテキストは背景色を**none**にする
- 図形の余白は**30px**以上取る
- 図形同士、図形とグループ境界、図形と線の間には最低 `30px` の余白を確保する
- 図形のラベルも図形領域の一部として扱い、ラベルが他の図形・線・グループ境界と重ならないようにする
- 線はサービスアイコン、ラベル、グループタイトルの上を通さない
- 線がサービスアイコンやラベルの上を通りそうな場合は、図形の配置を変えるか、余白のある外周側を通す
- 図形は検索をしてスタイルを取得しサイズの調整と図形の配置を行う
- 矢印や線は `common` カタログのコネクタ定義を使用し、手書きで `edgeStyle` を組み立てない
- 直角の矢印は `common/orthogonal-arrow`、直角の破線矢印は `common/orthogonal-dashed-arrow` を使用する
- 直角の矢印では `rounded=0` を維持する。`rounded=1` は角が丸く見えるため使用しない
- 線上のテキストは原則として使用しない
- 通信種別や用途は、線の色・線種と凡例で表現する
- 線の色・種類は凡例に定義されたものに沿って配置し、凡例にない色や線種を使わない
- `HTTPS`、`HTTP`、`DNS`、`SQL` など一般的なプロトコル名だけの線ラベルは省略する
- 図を作成する前に、ネットワーク構成図、アプリケーション構成図、ワークフロー構成図のどれを主目的にするかを判定し、その図種別に合う配置ルールを優先する

## 線の交差回避ルール

- 主通信経路を最優先し、左から右または上から下へ一方向に流れるように配置する
- 主通信経路の線は、監視・ログ・管理系の線より短く、直線的に見えるようにする
- 線が交差しそうな場合は、以下の優先順で回避する
  1. 図形の配置を調整して、主通信経路を一直線に近づける
  2. 監視・ログ・管理系サービスを図の外周寄りに移動する
  3. 監視・ログ・管理系の線を破線にし、主通信経路との視覚的な優先度を下げる
  4. 同種の線をまとめられる場合は、既存のAWSサービスアイコン、代表サービスノード、または集約線にまとめる
  5. どうしても交差する場合は、主通信経路ではなく補助線側が交差するようにする
- 線と図形の重なりは線同士の交差より優先して避ける。線がサービスアイコンやラベルを横切る配置は不可とする
- 監視・ログ・管理系サービスへの線は、複数の送信元から直接引かず、既存のAWSサービスアイコン、代表サービスノード、または集約線にまとめてから接続する
- 監視・ログ・管理系の集約を表すために、吹き出し、注釈、ラベルだけの中継図形、雲形、付箋風の図形を追加しない
- 監視・ログ・管理系サービスは主通信経路の上端または下端に配置し、主通信経路と線が重ならないようにする
- 線の折れ曲がりは少なくし、不要なウェイポイントは追加しない
- draw.ioの自動ルーティングに任せるため、edgeには原則として手動のpointsを設定しない
- 線ラベルは、凡例だけでは意味が伝わらない重要な通信差分がある場合に限る
- 線ラベルを使う場合も、線上ではなく近接する注釈テキストとして配置し、線や図形と重ならないようにする

## 図形検索

図形の draw.io `style` は、`scripts/shape-catalog.ts` で検索して使用する。
直接 style 文字列を新規作成するのは、カタログに該当図形が存在しない場合に限る。

利用可能な図形一覧を確認する:

```bash
tsx scripts/shape-catalog.ts list
tsx scripts/shape-catalog.ts list common
tsx scripts/shape-catalog.ts list aws
```

特定の図形の style を取得する:

```bash
tsx scripts/shape-catalog.ts style common arrow
tsx scripts/shape-catalog.ts style aws vpc
tsx scripts/shape-catalog.ts style aws application-load-balancer
```

矢印、線、汎用矩形、テキスト、DBシリンダーなどプロバイダー非依存の図形は `common` カタログを使用する。

## 図の検証

AWSのdraw.io XMLを作成した後は、`scripts/aws-validate-diagram.ts` で客観的なレイアウト検証を行う。

```bash
tsx scripts/aws-validate-diagram.ts path/to/diagram.xml
```

検証対象:

- AWSサービスアイコン同士が重なっていないこと
- AWSサービスアイコンがAWS Groupの枠線に重なっていないこと
- AWSサービスアイコンがラベル込みでAWS Cloud内に収まっていること
- 線がAWSサービスアイコンやラベル領域の上を通っていないこと
- 矢印や線同士が同じ経路上で重なっていないこと

検証スクリプトは未圧縮のdraw.io XML（`mxGraphModel`）を入力にする。圧縮済みURLや画像は検証対象にしない。
